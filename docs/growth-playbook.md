# Signature Scan growth playbook

## Purpose and boundaries

Grow qualified search visits that lead to downloads of **Signature Scan: Sign PDFs**, also known as **SignDocs**. The initial markets are United States/English (`en`), Türkiye/Turkish (`tr`), Germany/German (`de`), and Spain/Spanish (`es`). The owner is Damas Technologies LLC. The public website is https://scansignature.app/ and the app ID is 6805875185. Work only in this website repository. Preserve its design, static Vinext export, custom domain, existing legal disclosures, and GitHub Pages deployment.

The daily agent may publish one useful new guide or one substantial existing-guide update total per Istanbul calendar day across all locales. Skipping is a good outcome when there is no useful, verifiable change. Do not create near-duplicate pages for keyword variants, backdate articles, refresh modification dates without changes, claim tests that were not performed, fabricate authors/reviews/results, or publish bulk AI content. Follow https://developers.google.com/search/docs/fundamentals/creating-helpful-content.

App facts: iOS/iPadOS 26 or later; scan paper to multipage PDFs; capture handwriting on paper; crop and remove paper backgrounds; compare Clean/Balanced/Bold extraction; preserve supported ink colors; save/reuse/rename/delete local signatures; open PDFs from Files; place and resize signatures; create separate signed copies; reopen Recent Docs and share through compatible apps. Processing runs on device. Sharing, cloud retrieval, installation, and purchase/restore flows have separate connection requirements. Free exports are limited; do not promise unlimited free use. Do not invent OCR, PDF merging, standalone PNG export, encryption, identity verification, certificate signatures, or legal validity. Verify changing facts against the current App Store listing and product documentation. Do not alter the iOS app or store listing.

## Data and topic selection

The collector compares complete 28-day periods with a three-day buffer using Pacific reporting dates, requests finalized Search Console data for each market's web searches, paginates query/page/device rows, and separately requests totals. It filters United States/English by `usa`, Türkiye/Turkish by `tur`, Germany/German by `deu`, and Spain/Spanish by `esp`, then keeps each report attached to its matching locale path. Search Console can omit anonymized and lower-volume queries. Position is an aggregate, not an exact keyword ranking. Never imply causal ranking lift from one day's movement. Missing data in one locale does not invalidate the others and must not be reported as zero.

Prefer relevant non-brand searches with impressions, low CTR, and average positions 4–50. The scripted opportunity score is a triage aid, not a publishing instruction. Inspect intent, existing coverage, mobile/tablet relevance, and factual usefulness. Improve the page that already owns the intent before adding another. Twenty impressions is an initial triage threshold, not evidence of commercial demand.

When data is sparse, research an unserved problem from this backlog: signatures with faint strokes; scanner glare/cropped page troubleshooting; checking a signed PDF before email; capturing black/red/dark-blue ink; retaining the unsigned original; reusing a signature on iPad; local PDFs versus cloud placeholders. Check the published library before using any topic. Search primary sources and verify actual app steps. Avoid legal, tax, medical, identity-document storage, and security claims beyond demonstrated product behavior.

Keyword Planner adds demand context through the separate profile `scansignature-keywords` and patched `.tools/gum-keywords` binary. The collector maintains independent 30-day caches for US/en, TR/tr, DE/de, and ES/es; each request targets only its market, language, and Google Search. Fresh caches are reused and keyword failures never hide Search Console results. No additional Google API service or OAuth scope is required for these locale targets: existing Search Console and Keyword Planner access covers them. See `docs/keyword-planner.md` for targeting IDs, API approval, reproducible builds, CSV imports, cache format, and recovery. Google retired developer tokens on 2026-09-09; production access now belongs to the OAuth Cloud project. Basic access is needed for KeywordPlanIdeaService; Explorer is insufficient. Do not invent a developer token or use the old API Center application flow.

Read `.growth/latest.json` and its `markets` data. Use only the matching locale's ready Search Console report and fresh keyword cache; never combine search estimates across countries or languages. Candidates and exact-text coverage matches are aids, not proof of an unserved intent. Review the full localized library before deciding. Close variants can share an estimate: do not sum them or infer an exact search count from a range. Advertising competition is not an organic difficulty score. Treat missing metrics as unavailable, not zero.

If Google requires a passkey or another account-security step, the operator must complete it. Do not bypass the check. While API authorization or Basic access is pending, use an authentic Keyword Planner CSV whose country, language, and Google Search network match the cache being refreshed. Import requires explicit targeting and the original export date; re-importing stale data does not make it fresh.
